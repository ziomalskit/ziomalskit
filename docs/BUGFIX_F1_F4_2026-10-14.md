## F1: durable cost admission fence

An active session cost guard closes new Prompt/Render dispatches when its cost
cannot be verified. Missing CLI/instance/price, timeout, malformed, negative,
boolean or nonfinite price is unknown telemetry. Observations expire after
15 seconds; admission also projects the current controller-session estimate
from the verified hourly rate so it cannot use an old below-limit value.

The independent durable `cost_hold` never replaces the lifecycle plan. Both
schedulers and the final synchronous submission boundary check it before the
durable UUID/POST arm. A lost observation during asynchronous preparation
therefore defers the job without a new submission. Already running work and
reconciliation continue. Unknown cost does not arm STOP or DESTROY. Existing
known-limit stop-after-current behavior remains; manual STOP stays available.

Enabling/changing an active limit and restarting the controller require explicit
verification/resumption. Restored telemetry alone does not clear a hold.
The panel shows the reason and offers **VERIFY COST & RESUME DISPATCHES**.
This authenticated action obtains fresh below-limit telemetry and checks the
control generation again after the await. A newer lifecycle/settings decision
cannot be overwritten by a late response. It changes only cost admission;
an independently armed shutdown plan remains armed. Disabling the guard by an
explicit setting of zero removes that protection; cancelling a shutdown plan
does not clear a cost hold.

Cost state writes use the existing durable atomic writer. A write failure keeps
the in-memory hold, preserves more important lifecycle decisions, and requires
explicit retry. An unreadable lifecycle file is preserved. On boot an active
guard closes admission before any fresh paid dispatch, regardless of an old
persisted open observation. Diagnostics distinguishes health (`ready`, needed
also for safe STOP) from paid admission (`dispatch_ready`, `cost_guard_error`).

**This estimates the current controller session. It is not a hard limit on the
total Vast bill, storage, transfer charges or charges from previous sessions.**
Phase 1's separate quote/billing/deadline and operator STOP responsibilities
remain mandatory; the panel guard is not used by the isolated bootstrap.

## F3: complete, fenced upload publication

Every input-directory ancestor is opened/created through dirfds with NOFOLLOW.
Uploads write to a caller-owned O_EXCL/NOFOLLOW private temporary, flush/fsync
the complete copy, then atomically rename with no replacement. Existing files,
live links and dangling links are collisions and remain untouched; publication
retries a fresh name. No check-then-open window follows a link outside input.
Read/copy failures expose no partial final filename. Cleanup only removes the
current invocation's own temporary; retained unknown files are not collected.

## F4: atomic GGUF publication and retry

The hardlink/unlink window is replaced by Linux `renameat2(RENAME_NOREPLACE)`
using the already-open trusted directory descriptor. Unsupported systems or
filesystems fail closed, without a non-atomic hardlink fallback. Full source and
copied-data SHA256/size checks and file fsync still precede publication. Directory
fsync follows rename. A verified reuse also syncs that directory, completing
durability after a prior hard exit before directory fsync.

A hard kill before rename leaves an unpublished private partial and resumable
provider staging. Retry preserves retained unknown partials. A hard kill after
rename leaves a single-link correct final file; bootstrap plan accepts it and
full SHA256 verification reuses it without download. Destination/name/symlink
races cannot overwrite another owner's entry. A collision with the temporary
name never authorizes deleting that unowned file.

Legacy stores already damaged by the old two-hardlink publication still fail
closed. There is no automatic deletion/repair of unknown links: preserve them
and use separately reviewed exact-inode/checksum inspection before manual repair.
