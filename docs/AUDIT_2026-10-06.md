# AJ — ponowny audyt działania i kompatybilności

Data: 6 października 2026. Zakres: wszystkie otrzymane załączniki, bieżący RC5, workflowy lokalne/96 GB, mapy API, manifesty, panel, instalator, testy i historyczne materiały pomocnicze. Dokumenty przekazania potraktowano jako opis zamierzeń; twierdzenia o działaniu sprawdzano w kodzie i testach.

## Wynik dla użytkownika

**Projekt da się rozwijać w przygotowanym repozytorium, a panel działa w środowisku CPU. Oryginalny RC5 nie jest gotowy do niezawodnego renderowania na Vast.ai.** Wykryte problemy obejmują zarówno instalację, jak i rzeczywiste błędy obsługi zadań. Przeniesienie projektu na GitHub samo ich nie usuwa.

Projekt to mobilny system H3 Ref2VA: Picture 1 stanowi główną referencję, pięć pozostałych obrazów ją wspiera, audio jest opcjonalne. JoyCaption analizuje cały obraz i dziewięć nakładających się wycinków, Qwen sprawdza detale, Gemma analizuje referencje, a Violet-Lotus tworzy końcowe prompty. Docelowy render ma dwa przebiegi i działa na native INT8. Panel rozdziela 10 kandydatów na pięć automatycznych i pięć do zatwierdzenia.

Oryginalną paczkę zachowano bez zmian. Naprawy logiki aplikacji i workflowów wymagają osobnego etapu prac nad kodem z zachowaniem tego baseline. Przygotowanie developerskie obejmuje dodatkowe pliki konfiguracyjne i testowe; nie zmienia oryginalnych modeli, lockfile ani kodu RC5.

## Workflowy, modele i cache

- Mapowanie obrazów i upstream seedów odpowiada zamierzeniom. Rodzicielski controller 4022 dostaje wspólny analysis seed oraz osobne seedy kreatywne. Konwerter 1.21.0 prawidłowo uwzględnia rodzicielskie widget overrides modelu/seedów; odmienne wartości domyślne w definicji subgrafu same w sobie nie są błędem.
- Kopia API mapy wewnątrz RC5 zawiera klucze `workflows` i `prompt_capture`; samodzielny starszy manifest ich nie ma. Nie podmieniać jej starszą kopią o podobnej nazwie.
- Samodzielny master 96 GB zawiera pozostałości unload/starych linków usunięte w kopii RC5. Repo zachowuje obie wersje jako materiały, lecz do sterownika odnosi się wersja RC5.
- W podgrafie Stitch RC5 zostały dwa nieużywane stare linki 46252/46253. Analizowany konwerter rozwiązuje interfejs innymi linkami i je ignoruje. To wymaga uporządkowania, ale nie jest wykazanym blockerem obecnej ścieżki.
- Wystarczająco duży kontekst LLM nie został udowodniony. Step 0C ma ctx 12288; nominalne limity caption+tiles+Qwen+wynik sumują się do 12050, pozostawiając za mało rezerwy na instrukcje, template i obraz. Jest to ryzyko do zmierzenia rzeczywistym tokenizerem/logami, nie dowód, że każda próbka przekroczy limit. Długi template Step 1 też wymaga pomiaru.
- Manifest jest listą nazw plików, nie instrukcją pobrania z weryfikacją. Nie zawiera kompletu repozytoriów, rewizji, rozmiarów i SHA256. Instalator nie pobiera wymaganych wag.
- Sprawdzenie istnienia wag nie wykrywa pustego/uszkodzonego safetensors, złego mmproj ani brakującej rejestracji folderu loadera. Trzeba zachować TLS/signature/checksum verification i sprawdzić faktyczny loader.
- Cache Step 0–2 jest zamierzony, ale nie został potwierdzony na GPU; osobne procesy mają osobne cache.

## Dodatkowe ograniczenia instalatora i dokumentacji

Instalator zapisuje hasło bez shellowego cytowania do `runtime.env`; hasła ze spacjami, `$` lub cudzysłowami mogą zepsuć start albo zostać zinterpretowane przy `source`. Wypisuje też hasło i zmienia losowane hasło po ponownej instalacji. Nie uruchamiano go tutaj, więc nie wygenerowano ani nie ujawniono produkcyjnych danych dostępowych.

Trzy fallback repozytoria pobierane są z ruchomego HEAD; wymagania panelu RC5 mają tylko minima wersji. Nowy lock obejmuje panel developerski CPU, nie pełny stos GPU. Kompilacja llama używa wszystkich rdzeni i usuwa poprzedni build; wymaga doboru równoległości i ponownego wykorzystania poprawnych wyników.

Preflight ma porty wpisane na stałe i sprawdza tylko część klas custom nodes. Sam smoke `--print-prompt` nie dowodzi poprawnego wysłania grafu. **Zwykły batch panelu nie jest trybem prompt-only:** automatycznie zleca render pięciu kandydatów. Tego nie należy używać jako testu bez renderu.

## Przygotowana konfiguracja i kolejność dalszych prac

Repozytorium ma nowy README, wskazówki dla agentów, ochronę sekretów/stanu/dużych modeli przez `.gitignore`, zachowanie bajtów migracji przez `.gitattributes`, Python 3.12, hashowany lock panelu, polecenia `make`, testy HTTP i workflow GitHub Actions dla CPU. Lokalny panel ma osobną kopię stanu, wygenerowane hasło w ignorowanym pliku i wyłączony dostęp do CLI Vast. Oryginalne testy uruchamiane są w kopii tymczasowej.

Najpierw należy poprawić instalację/LLM/konwerter i błędy recovery/lifecycle, potem odizolować render od autopromptera. Następnie ustalić zaufane źródła modeli i przeprowadzić [akceptację GPU](GPU_ACCEPTANCE.md). Pełny batch i automatyczne pilnowanie kosztów powinny być sprawdzane po pojedynczym poprawnym renderze.

Publikacja środowiska, uruchomienie GitHub Actions po push i odtworzenie świeżej maszyny to odrębne zdarzenia; lokalne testy nie dowodzą, że już nastąpiły.
